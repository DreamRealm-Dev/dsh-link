# dsh-link/rust — native compute core

The napi-rs addon behind the `dsh-link-compute` Cordis host plugin (R486 MVP). It carries two pure
functions and one identity probe:

| N-API export | Rust entry | Input | Output |
|---|---|---|---|
| `foldCollabRecords` | `fold::fold_collab_records` | JSON array of `dsh-link-collab` control records | canonical summary JSON (counts, member registry, task board, team tree, checksum) |
| `indexTeamStatus` | `team::index_team_status` | JSON array of `team/member`/`team/task`/presence events | canonical team-status JSON (roster with parent/children/depth, team rows, counts, tree, checksum) |
| `nativeVersion` | `native_version` | — | crate version, so a loader can report which half ran |
| `probe` | `probe` | — | `{ok, nativeApiVersion, features}`; the host plugin refuses a mismatched addon |

The addon also exports the stateful `CollabFoldIndex` class (the incremental API): `new`,
`appendBatch(recordsJson)` (JSON array string), `appendRecords(ndjsonBuffer)` (**byte-batched**,
the collaboration log's own on-disk NDJSON), `snapshot()`, `deltaSince(version)`,
`readDelta(cursor)` (**byte-batched** delta), `version()`, `records()`, `checksum()`. Its state
keeps the fold accumulators in Rust, so an append parses and folds only the new batch;
`snapshot()` is byte-identical to the one-shot fold over the concatenation of the appended
batches. The binary layouts of the byte-batched buffers are documented in
`crates/dsh-compute-napi/src/wire.rs` and mirrored by the TypeScript reference.

`probe()` is the capability handshake: it reports `nativeApiVersion` (an integer that changes
incompatibly) and the `features` this build offers. The host plugin requires
`nativeApiVersion === 1` and every feature it uses, and falls back to the pure-TS reference
otherwise (with the reason in `detail`). See `docs/handoff/R497-compute-batching.md`.

Both functions are pure: no I/O, no globals, no clock. "Last wins" decisions compare `(seq, index)`
instead of read order, and the fingerprint is a commutative sum of per-row FNV-1a 64-bit hashes, so a
re-ordered input folds to the same bytes. Malformed rows are counted, never guessed at.

The JavaScript-visible names are camelCase; the TypeScript declarations are generated by napi-rs at
build time (`index.d.ts`) when the `@napi-rs/cli` is used. This MVP builds with plain `cargo`
instead — the `.d.ts` in `plugins/dsh-link-compute/src/reference.ts` types is the hand-written
mirror — because it keeps the native build to one toolchain.

## Build and verify

```powershell
cd <workspace>\\dsh-link
node rust/scripts/build.mjs        # .build.lock -> cargo build --release -> plugins/dsh-link-compute/lib/dsh_compute.node
node rust/scripts/smoke.mjs        # PASS = require works, parity holds, no unsafe in crate sources
node --expose-gc rust/scripts/bench.mjs              # stateless (one-shot) paths
node --expose-gc rust/scripts/bench-incremental.mjs  # stateful CollabFoldIndex vs TS incremental
node --expose-gc rust/scripts/bench-batched.mjs      # batching multiple + byte-batched vs TS
node rust/scripts/verify-r497-numbers.mjs            # R497 doc numbers + §3/§4 coverage vs archived runs
node rust/scripts/verify-r497-numbers.mjs --self-test  # proves the coverage check catches a leaked number
node --test rust/scripts/bench-out-atomic.spec.mjs   # concurrent --out claim: exactly one winner
node rust/scripts/compare-bench-runs.mjs --baseline-manifest rust/bench-runs/baseline.json --current "rust/bench-runs/bench-batched-*-<label>*.json"
```

`build.mjs` serialises itself through the repository convention `dsh-link/.build.lock` (a directory):
it waits up to 20 minutes for a peer build, creates the directory, builds, and removes it in a
`finally` block. `cargo test -p dsh-compute-napi --release` runs the Rust unit tests and does not
need Node.

## Incremental API

`CollabFoldIndex` keeps `FoldState` (the same accumulators the one-shot function uses) behind a
mutex and appends batches into it. The snapshot is exactly `fold_collab_records` over the
concatenated batches — asserted in `cargo test`, `smoke.mjs` and the benchmark — and every
`deltaSince(version)` is the per-batch kinds/records summary kept since that version. One native
call failure cannot be replayed into a fallback index (the state lives in the handle), so a
consumer that needs the pure-TS fallback reopens the index with `nativeEnabled: false`.

Benchmark runs are archived per invocation (\`rust/bench-runs/\`, unique \`runId\`, never
overwritten); cite the archived file when quoting a number, and run
\`node rust/scripts/verify-r497-numbers.mjs\` to prove a document's numbers still match.

## CI and distribution (documented, not wired in this checkout)

The maintainable form of this crate's CI and its prebuilt-only distribution plan live in
`docs/handoff/R497-compute-batching.md` sections 6 and 7. The short version: `cargo fmt --check`,
`cargo clippy --release --all-targets -- -D warnings`, `cargo test` (or nextest), a release build,
and the Rust-vs-TS differential smoke are the gates; distribution ships prebuilt platform packages
(`os`/`cpu`-gated `optionalDependencies`) behind the `probe()` handshake, never an install-time
compile.

## Safety rules

- The crate source contains **no `unsafe` blocks**; `smoke.mjs` fails if one appears. The only
  unsafe code in the built addon is what `napi-derive`'s macro expansion emits at the FFI boundary.
- Every N-API entry wraps its body in `std::panic::catch_unwind`; a panic becomes a JS error
  (`COMPUTE_PANIC: ...`) instead of aborting the kernel process.
- The release profile keeps `panic = "unwind"` (the default) — `panic = "abort"` would defeat that
  guard.
- The functions are synchronous and bounded by the input size. The host plugin decides whether a
  call is small enough to run inline; move a call to `AsyncTask` before feeding it megabyte-scale
  ledgers on the event loop.
