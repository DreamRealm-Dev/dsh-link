# ADR-003：桌面端与手机端的前端契约

**状态**：生效。**依据**：`docs/handoff/R1-critique.md` 阻塞项 3（代码可证部分）+ 用户需求行 15 / 37 / 286。

## 决定

1. **桌面端 = 官方客户端 + 客户端插件**，**不自研前端**。窗口加载的是 shell 代理（`src-tauri/src/lib.rs:344-360`），`dist/index.html` 只有 33 行、自述 "This bundle is never what the user sees"（`src-tauri/tauri.conf.json:7` 的 `frontendDist: ../dist`）。
2. **手机端 = 自研 UI**（手机上没有本地内核可加载），但**复用同一套契约**：host 插件（cordis 服务）、capability 词汇表（`compat/`）、互联协议（broker / RPC）。
3. 明确共用与独占：

| 层 | 桌面 | 手机 |
|---|---|---|
| host 插件 / 服务契约 | 共用 | 共用（通过互联层或本地内核） |
| capability 词汇表 + 翻译层 | 共用 | 共用 |
| 互联协议（发现/配对/权限衰减） | 共用 | 共用 |
| UI 皮肤（slot 注入：玻璃材质、品牌） | **桌面独占**（依赖官方客户端的 slot 体系） | 不适用（自研 UI 自己实现风格） |
| 窗口框架（shell：透明窗、连续圆角、标题栏） | **桌面独占** | 不适用（系统窗口） |

## 为什么

- 桌面写自研前端 = 放弃官方 slot 体系 → 官方插件生态全部失效，行 39「一切皆插件」变成空话（这是 R1 阻塞 3 的核心）。
- 手机不可能加载官方桌面客户端（没有本地内核、也没有桌面 WebView 环境），只能自研 UI；若两边都不记录，团队会在「做自研 React 外壳」与「只写客户端插件」之间反复摇摆，而 C1/C2/C10/C14 全都挂在这条线上。
- 桌面内部跨层契约已跑通（`docs/handoff/R2-lead-g3.md`：窗口与皮肤读同一个 `corner-shape` token，三态 2.48/3.52/2.48 px）——**这只证明桌面内部可行，不证明手机端能复用 capability 词汇表**；本 ADR 的第一版曾把它当作后者，属过度引用，已按 critic 复核（`docs/handoff/R2-critique.md` §2.3）改正。
- **手机上词汇表由谁执行（本轮补决定）**：`compat/` 是 host 插件、跑在内核进程里，手机上没有本地内核，因此第一期手机端**不执行词汇表**，走「桌面内核代执行 + 手机只做 UI 与 RPC 客户端」（选项 a）。选项 b（手机自带一份表 + 解析器）保留为后路，代价是 `compat/**` 必须是**可移植的纯数据/纯函数包**（不依赖 `ctx.reflect`；目前已做到 `membersOf/valueOf` 可注入，这是它成为后路的唯一原因）。

## 影响面（会返工什么）

- 若违反第 1 条：窗口要么变成自研 UI（丢 slot），要么变成"官方客户端 + 一堆注入字符串"（把 UI 定制做成补丁堆，升级即碎）。
- 若违反第 2 条：手机端会出现第二套插件契约，互联层要从两套身份体系里做映射。

## 回滚方式

手机端可退化为**薄客户端**：只做"远程接续桌面会话"（需求行 259 的跨端接续），自研 UI 缩到会话列表 + 输入框，把大部分能力留在桌面。该退化不触碰契约层，是廉价回滚。
