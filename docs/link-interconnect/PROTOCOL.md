# link-interconnect/1 — protocol specification

Status: **stable from M1** (R472). Machine-readable form: `GET /link/v1/contract`, answered by the
running DSH-LINK at its shell origin (default `http://127.0.0.1:31761`). If a field changes meaning, the contract
version changes; dropping or renaming an endpoint is a major-protocol change.

## 1. Roles and directions

There are two directions in one protocol:

- **Software adapts to LINK (software-active, M3).** The software serves a declaration and an invoke
  endpoint; LINK reads the declaration, asks the person, then calls the software. LINK pulls; the
  software never opens an inbound connection to LINK.
- **LINK adapts software (LINK-active, M2).** LINK probes a declared installation (file / port / health
  fingerprint), asks the person, then binds the software as (for the shipped adapter) an OpenAI-compatible
  model provider. Not covered by this document; see `ADAPTERS.md`.

## 2. Discovery

A software peer publishes one document:

    GET {origin}/.well-known/link-interconnect.json

Its body is a `PeerManifest`:

| Field | Required | Meaning |
| --- | --- | --- |
| `protocol` | yes | `link-interconnect/1`. A different major is refused with `link/version-unsupported`. |
| `identity.linkId` | yes | Immutable peer id (the token subject and the grant key). |
| `identity.name` | yes | Human alias, shown in the consent card. |
| `identity.vendor` | no | Vendor label, shown in the card. |
| `endpoints.invoke` | yes | Absolute path (starts with `/`) of the invoke endpoint. |
| `endpoints.events` | no | SSE endpoint, if the peer publishes progress. |
| `capabilities[]` | yes | At least one known capability; unknown kinds are ignored by name. |
| `limits.rpm` | no | Peer-side request ceiling, copied into the grant. |

Reaching a peer origin is deny-by-default: loopback always, any other host only when named by the
LAN allowlist (`link-interconnect/lan-allowlist.json` in the kernel home, or `LINK_PEER_ALLOWLIST`;
see `LAN.md`). Redirects are not followed.

## 3. Identity and tokens

- Each DSH-LINK instance has one Ed25519 key pair at `<DSH_HOME>/link-interconnect/identity.json` and
  `linkId = base32(sha256(public key))[0:26]`. The id is derived from the key, never from a name.
- Requests authenticate with a bearer **compact JWS** (`alg: EdDSA`) whose claims are
  `{sub, aud, scope[], iat, exp, jti}`. Lifetimes: access 15 min, refresh 30 days, embed 10 min
  with `aud = the framing origin`. A revoked `jti` is refused immediately (blacklist persisted).
- A software peer that wants to authenticate its callers can publish a pairing **code** flow:

      POST /link/v1/handshake          {protocol, client:{linkId,pub,platform}, scopes[]}
        -> {challenge, expiresIn}
      POST /link/v1/handshake/confirm  {challenge, signature, pairingCode}
        -> {accessToken, refreshToken, scopes, expiresAt, peer:{linkId, name}}

  The code is generated by the LINK instance at start and is readable by the person
  (`<DSH_HOME>/link-interconnect/pairing.json`, or `LINK_PAIRING_CODE`). It never appears in the contract.

## 4. Invoke and events

    POST /link/v1/invoke        Authorization: Bearer <token>
      { "cap": "<capability kind>", "op": "<operation>", "args": <json>, "idempotencyKey"?: "<string>" }
      -> { "ok": true,  "result": <json> }
      -> { "ok": false, "error": { "code": "<stable code>", "message": "<sentence>" } }

The same `idempotencyKey` answers the first result again for 10 minutes and marks the replay with an
`x-link-idempotent-replay` response header. Body ceiling: 1 MiB (`link/payload-too-large`).

    GET /link/v1/events?token=<token>
      -> text/event-stream of {callId, seq, type, at, data}; the backlog (last 200 events) is replayed
         first, then the stream follows live events, with keep-alive comments every 15 s.

## 5. Error codes (stable; HTTP status in brackets)

| Code | Status | When |
| --- | --- | --- |
| `link/unauthorized` | 401 | missing/invalid/revoked token, wrong audience |
| `link/scope-missing` | 403 | valid token without the capability's scope |
| `link/version-unsupported` | 400 | declaration or handshake speaks another major |
| `link/consent-required` | 409 | the person denied, or the question expired |
| `link/peer-unavailable` | 502 | the peer or the proxy upstream did not answer |
| `link/rate-limited` | 429 | over the per-key/peer ceiling; `retry-after` is set |
| `link/payload-too-large` | 413 | body over the ceiling |
| `link/idempotency-conflict` | 409 | same key, different operation |
| `link/bad-request` | 400 | malformed request or disallowed origin |
| `link/not-found` | 404 | unknown endpoint / unknown op |
| `link/method-not-allowed` | 405 | wrong verb; `allow` header names the accepted one |
| `link/internal` | 500 | a real fault inside LINK |

## 6. Capabilities

**models.provide** (software -> LINK; the peer exposes an OpenAI-compatible surface):
the peer declares it, LINK reads the catalog from `GET {origin}/v1/models` and serves completions from
`POST {origin}/v1/chat/completions` through a kernel provider route. Scope: `models.provide`.

**tools.expose** (software -> LINK; the peer publishes tools LINK may call):
the peer declares `tools:[{name, description, parameters, call?}]`. LINK registers one kernel tool per
declaration (registration names are provider-safe: `echo.ping` becomes `echo_ping`, the original is
kept in the description) and calls back:

    POST {endpoints.invoke}  { "cap": "tools.expose", "op": "<declared name or call.op>", "args": <tool args> }

Scope: `tools.expose`. A tool error is a thrown tool error naming the peer's stable code.

**session.embed** (LINK -> software; a software UI embeds one LINK session):
the software asks LINK for a short-lived token and frames the embed page:

    POST /link/v1/embed/token     {sessionId, mode: "sidebar"|"full", origin}
      -> {token, expiresAt, url}          (token: 10 min, aud = origin)
    GET  /link/v1/embed/session?token=<token>&nonce=<nonce>
      -> a self-contained page whose CSP is `frame-ancestors <origin>`; it postMessages
         {type:"link:embed:ready", v:1, nonce} to that origin. Without the token: 401. Revoked jti: 401.

Scope: `embed.session`.

**models.proxy** (LINK -> software; the software calls LINK's model channel):
an admin mints one proxy key (`lk_...`, shown once, stored only as sha256) with a model whitelist and a
per-minute ceiling. The software calls:

    POST /link/v1/openai/v1/chat/completions      (Bearer lk_...)
    GET  /link/v1/openai/v1/models
    POST /link/v1/anthropic/v1/messages           (and GET .../v1/models)

Answers: 200 forwarded / 401 unknown or revoked key / 403 `link/scope-missing` outside the whitelist /
429 `link/rate-limited` with `retry-after`. Scope: `models.proxy`.

## 7. Contract document

    GET /link/v1/contract

Read-only and byte-identical for identical input; it carries `protocol`, `version`, `endpoints[]`,
`caps[]`, `scopes[]`, `limits` and the CSP template. It is the one document to integrate against:
paths and codes here and there cannot drift apart.

## 8. Versioning

The protocol id is `link-interconnect/<major>`. Same major: fields may be added, never renamed or given a
new meaning; unknown capabilities are ignored by name. A new major is a refusal
(`link/version-unsupported`), never a silent best-effort.
